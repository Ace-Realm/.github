# Contributing to Ace Realm

First off, thank you for considering contributing to Ace Realm! We build utility-first software, developer tools, and user applications designed to eliminate daily friction.

Whether you are fixing a bug, proposing a feature, writing documentation, or creating content, this guide will help you get started.

---

## 1. Code of Conduct & Philosophy

We value clear, maintainable, and reliable software. When contributing, keep our core engineering principles in mind:
* **Simplicity over complexity:** Solve single problems cleanly. Avoid bloated platforms.
* **Readable & secure:** Write self-documenting code. Never commit secrets, credentials, or API keys.
* **Engineering over hype:** Focus on utility and actual problem-solving.

---

## 2. How to Contribute

### A. Technical Contributions (Code, Docs, & Infrastructure)

1. **Find or Create an Issue:**
   * Browse open issues on our repository. Look for tasks labeled `good-first-issue` if you're new.
   * If you want to introduce a new feature or fix a bug that isn't listed, open an issue first to discuss it before submitting code.

2. **Branching Naming Convention:**
   Create a local branch using one of the following prefixes:
   * `feat/short-description` (for new features)
   * `fix/short-description` (for bug fixes)
   * `docs/short-description` (for documentation updates)
   * `chore/short-description` (for build, tooling, or minor updates)

3. **Pull Request (PR) Requirements:**
   * Ensure your code runs locally without breaking existing functionality.
   * Do not include unnecessary formatting changes, unused dependencies, or stray debug logs.
   * Keep PRs focused on a single task or issue to make reviews straightforward.
   * Title your PR clearly and link it to the relevant issue (e.g., `Fixes #12`).

### B. Content & Growth Contributions (Media & Tech Storytelling)

If you are joining as a content creator or growth contributor:
* **Propose Ideas via Issues:** Use repository issues or the team chat (`#content-growth`) to pitch video demos, technical breakdowns, or launch materials.
* **Keep it Authentic & Clear:** Content should explain *how* tools solve real friction points rather than focusing on hype.

---

## 3. Communication

For quick questions, design discussions, or syncs, join our official communication channels:
* **Telegram / WhatsApp:** Check repository links or ping the maintainer for access.
* Keep technical discussions inside repository issues or designated `#dev` channels so decisions remain documented.
